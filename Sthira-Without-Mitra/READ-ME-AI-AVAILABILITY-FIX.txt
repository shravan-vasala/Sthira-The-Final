STHIRA - AI AVAILABILITY AND SCAN DIAGNOSTICS
===========================================

WHAT CHANGED
Photo scans temporarily skip a model that recently returned a busy response.
A model becomes eligible again after a 60-second cooldown. The existing
automatic fallback remains bounded by the analysis deadline.

If both models are cooling down, the scanner retains your photo and shows
the remaining wait. This avoids repeatedly sending the same failing calls.
Provider retry delays and rate limits are respected across photo retries.
Account/client changes and a different API key start fresh availability state;
late responses from an old key cannot change the new connection's routing.

Recent AI Activity now groups each scan, including its manual retry taps and
automatic requests. It shows time from the first tap, processing time, and
expandable request details. Timing stops when results are ready to review.
Diagnostics are kept in memory and do not record photos, paths, meal text,
API keys or raw provider response bodies.

The existing models, image settings and food-recognition prompt are unchanged.
This improves routing and measurement; it cannot guarantee a successful scan
when both provider models are unavailable.

CHECK ON YOUR PHONE
Try one photo scan. If the primary is busy and the fallback works, another
uncached scan during the cooldown should start with the fallback. Open
Recent AI Activity to see one grouped result and expand its attempts.
A retry of unchanged input in the same open scanner stays in the same group.
Changing the photo/hint/description starts a new group.
